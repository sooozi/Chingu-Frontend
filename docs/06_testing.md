# 06. Testing (Refactoring Safety Net)

리팩토링의 목적은 **결과물은 그대로 유지하면서, 코드의 구조와 품질만 개선하는 것**이다.
테스트는 이를 증명하는 유일한 방법이며, 리팩토링의 안전망이다.

이 문서는 리팩토링 과정에서 **어떤 테스트를, 어떤 기준으로, 어디까지 작성해야 하는지**에 대한 실무 기준을 정의한다.

---

## 1. 테스트의 기본 원칙

### 원칙 1. 테스트 없는 리팩토링은 리팩토링이 아니다

* 테스트가 없으면 변경이 개선인지, 버그인지 증명할 수 없다
* 리팩토링 전에 반드시 기준 동작을 고정한다

### 원칙 2. 모든 테스트는 “깨졌을 때 의미가 있어야 한다”

* 구현 상세를 검증하는 테스트는 리팩토링을 방해한다
* 사용자 관점의 결과를 검증한다

---

## 2. 회귀 테스트 (Regression Test)

### 목적

* 리팩토링 후 기존 기능이 망가지지 않았음을 보장
* “어제 되던 게 오늘 안 되는 상황” 방지

### 기준

* 기존 테스트는 **절대 삭제하지 않는다**
* 리팩토링 전 모든 테스트가 green 상태여야 한다
* 리팩토링 후에도 동일하게 통과해야 한다

```bash
npm test
```

---

## 3. 컴포넌트 단위 테스트 (Unit / Component Test)

### 대상

* 리팩토링으로 분리된 컴포넌트
* 조건 분기 / 상태 분기 로직이 있는 컴포넌트
* 재사용되는 UI 컴포넌트

### 도구

* Jest
* React Testing Library (RTL)

### 기준

* 구현이 아니라 **행동(behavior)**을 테스트한다
* className, state, hook 내부 구조 테스트 금지

❌ 지양

```ts
expect(component.state.isOpen).toBe(true)
```

✅ 권장

```ts
expect(screen.getByText('완료')).toBeInTheDocument()
```

---

## 4. E2E 테스트 (End-to-End)

### 목적

* 사용자 관점의 핵심 플로우 보장
* 프론트 + 백엔드 + 네트워크 통합 검증

### 대상 플로우

* 로그인 / 로그아웃
* 회원가입
* 결제
* 데이터 생성 / 수정 / 삭제
* 페이지 이동 흐름

### 도구

* Playwright (권장)
* Cypress

### 기준

* 모든 화면을 테스트하지 않는다
* “돈/데이터/권한”이 걸린 플로우만 테스트한다

---

## 5. 엣지 케이스 테스트

리팩토링 시 가장 많이 터지는 영역이다.

### 반드시 테스트해야 할 케이스

* 데이터가 null / undefined인 경우
* 빈 배열인 경우
* API 지연 / 타임아웃
* 에러 응답
* 권한 없는 사용자

```ts
expect(() => render(<List items={[]} />)).not.toThrow()
```

---

## 6. 테스트 작성 우선순위

모든 테스트를 다 작성할 필요는 없다.
아래 우선순위를 따른다.

1. 핵심 사용자 플로우 (E2E)
2. 리팩토링 대상 컴포넌트 (Component Test)
3. 버그가 자주 났던 로직
4. 상태 분기 / 조건 분기 로직

---

## 7. 리팩토링 전 / 후 체크리스트

### 리팩토링 전

* [ ] 기존 테스트 모두 통과
* [ ] 기준 동작 정의됨
* [ ] 수정 범위 명확함

### 리팩토링 후

* [ ] 모든 테스트 재통과
* [ ] 신규 컴포넌트 테스트 추가됨
* [ ] 엣지 케이스 테스트 추가됨

---

## 8. 기준 요약

* 테스트는 안전망이다
* 테스트 없는 리팩토링은 금지
* 행동을 테스트하고 구현은 테스트하지 않는다
* 중요한 흐름만 E2E로 보호한다
* 엣지 케이스는 반드시 코드로 남긴다

이 문서를 기준으로 모든 리팩토링 작업을 검증한다.
